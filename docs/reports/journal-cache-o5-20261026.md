# O5 — SWR/cache, tranche en attente de validation et intégration finale

Base 7bb3bfcb08d587cd4d4ce636626703ed58750b2e, même branche feat/journal-fullscreen-reading, enfant du lot backend d7b2272. Brief O5 relu; aucun Browser, aucun build VPS, migration/rollback toujours non appliqués. L'ancienne conservation partagée des réponses Journal dans Cache Storage est retirée.

## Implémenté

- GET Journal : ETag SHA-256 calculé après requireJournalOwner sur contenu + état + scope utilisateur/workspace; ne dépend pas des URLs signées tournantes. If-None-Match (liste/tags faibles) donne 304 sans corps, Cache-Control private/no-store et Vary Cookie. Le client omet If-None-Match quand les couvertures sont proches de l'expiration, pour renouveler leurs URLs.
- Module pur journal-cache.mjs : version 2, clés user/workspace/edition, TTL doux 60s, sept éditions / sept jours / 2MiB, merge stable par clé composite edition/item, overlay des statuts en attente. L'absence de ligne de statut côté serveur n'écrase pas un statut encore en file; hors de la file, la réponse serveur fait foi (permet Rouvrir).
- IndexedDB : racine et file dans un même object store, transactions readwrite atomiques, scope + génération. Une purge/switch invalide les écritures en vol qui porteraient un ancien token. Repli localStorage limité 250k caractères; erreurs stockage explicites. Préférences police/thème scoped dans cette même racine.
- Hook use-journal-data : getSession seulement pour identifier le cache local, jamais pour autoriser l'API; affichage cache avant fetch; revalidation fond focus/online/visibility et 60s visible; 304 sans parser de corps ni remplacer les données React. Abort et token de génération pour requêtes obsolètes. Les données existantes restent affichées en cas de panne, sans remettre le lecteur/scroll à zéro.
- Queue bornée à 100 opérations statut/progression, validation avant stockage et scope imposé; id stable, batchId de progression conservé pour rejeu RPC idempotent. Ack seulement après succès HTTP; reprise à online/revalidation. Optimisme statut et rollback d'un refus 4xx; une panne réseau conserve la file. Les réponses 503 (dont migration absente) laissent la file et un avertissement. Pas de tracker de lecture ajouté ici; le hook expose enqueue(kind=progress) pour le tracker de la tranche UI.
- Déconnexion : purge attendue avant signOut, notification storage pour autres onglets; événement SIGNED_OUT/changement de compte supprime cache/fichiers privés hérités. Changement de workspace purge la racine précédente (politique stricte). Le bouton Déconnexion reste bloqué si la purge échoue, au lieu d'annoncer une suppression non faite.
- SW : aucune réponse API ou HTML authentifiée n'est conservée. Pré-cache du shell public statique /journal-offline.html, JS/CSS/assets et assets Next publics bornés 150, actualisés en fond. Migration du SW v3 vers v4 supprime les anciens caches. Au démarrage hors ligne, le fallback public affiche la liste et les textes de la racine IndexedDB de ce navigateur via textContent (pas HTML libre). Les onglets déjà chargés gardent l'app et la queue hors-ligne.

## Non démontré / non terminé : O5 n'est PAS accepté comme complet

- Cache Storage des couvertures privées signées non ajouté : elles ne doivent pas être partagées entre comptes. Les URLs expirées sont retirées du cache applicatif. Les images privées ne sont donc pas garanties hors-ligne. Un transport de blobs explicitement scoped, invalidable avec la génération, reste à ajouter après revue.
- Le fallback froid est un lecteur statique minimal (liste et textes), pas le shell React plein écran O1/O2. Pas d'actions ni collecte de temps dans ce fallback; elles nécessitent l'app déjà ouverte. Le tracker et le branchement de ses deltas ne font pas partie de cette tranche.
- Le cache hors-ligne est une copie locale accessible à l'utilisateur du profil navigateur, pas une revalidation d'autorisation serveur. Un retrait distant de rôle ne peut pas être constaté sans réseau. Au prochain 401/403, purge immédiate. Pas de chiffrement ni de garantie sur un profil navigateur partagé; ne pas interpréter le namespace comme une autorisation distante.
- Seules les sessions localement connues peuvent retrouver le workspace hors-ligne. Une première ouverture sans session/cache nécessite le réseau. Les changements de scope purgent les éditions précédentes, par choix conservateur.
- 29 tests Node réussis (journal-cache, journal-progress, journal-quality, mausbot-journal, pwa-contract). Le cache est testé avec un adapter mémoire : les transactions IndexedDB réelles et le hook React ne sont pas exécutés dans Node. Le test 304 est un contrôle de contrat source, pas une mesure du nombre de rendus React. Tests JS syntaxe SW/fallback réussis.
- journal-reader.test.mjs ne charge pas : TypeScript absent (et React non installé). Lint/typecheck tentés : eslint/tsc introuvables. Build non lancé (interdit sur VPS). Pas de mesure <300ms, tests avion/multionglets/signout réels ni recette visuelle. SQL/RLS/concurrence restent non exécutés, comme rapport backend.

Prochaine action : intégrer la tranche UI au même brouillon, faire passer CI avec dépendances et tests de navigateur dans un environnement autorisé, puis compléter cache scoped des blobs et fallback complet avant acceptation O5. Ne pas merger, appliquer la migration ou promouvoir en production.
