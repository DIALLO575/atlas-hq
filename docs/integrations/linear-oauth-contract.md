## First implementation slice

- `packages/connectors/linear/src/contract.ts` records the Linear API endpoints, allowed OAuth scopes, and capability-to-scope mapping. Read access is the default; issue and comment creation use their targeted scopes. Broad `write` and `admin` are excluded, and writes are not enabled in the runtime contract.
- `oauth.mjs` builds a user-actor OAuth authorization URL with PKCE S256, validates HTTPS callback URLs (loopback HTTP only for local development), restricts scopes, and exchanges authorization codes server-to-server using form encoding. It validates the token response and returns only the required token fields; errors are allowlisted and do not include provider response bodies.
- `oauth-state.mjs` signs a 15-minute state bound to one ATLAS workspace and actor, stores only its SHA-256 hash through an atomic-store interface, checks the signed state against the HttpOnly cookie and verified callback actor/workspace, then consumes it once. The `atlas_linear_oauth_states` migration supplies a durable, RLS-enabled server-only ledger; it is committed but unapplied.
- `graphql-client.mjs` is a minimal no-store GraphQL transport. It does not log, cache, or serialize the bearer token into an application response. Provider errors are mapped to safe categories.
- `workspace-access.mjs` is a fail-closed policy predicate: the authenticated actor must match the queried workspace member, role must be `owner`, `admin`, or `member`, and requested ATLAS workspace must equal the linked workspace. Only owners/admins may manage a connection. Callers must obtain identity and membership from the verified ATLAS server session/database; caller-supplied role values are not authority.

This remains a non-live integration. The start route verifies the Supabase session and owner/admin membership, requires a fixed callback URI, stores a one-time state hash, and sets short-lived HttpOnly/Secure/SameSite cookies. The callback validates the same actor/workspace and atomically consumes the state. Callback exchange is disabled unless `LINEAR_OAUTH_CALLBACK_ENABLED` is explicitly `true`, the token keyring is valid, and the connection table is reachable; default configuration remains disabled. When enabled, it exchanges a one-time code, verifies the Linear viewer and organization IDs, then stores only AES-256-GCM ciphertext bound by AAD to both ATLAS and Linear actor/workspace IDs. The connection row is unique to the ATLAS actor and workspace, has no client grants or policies, and uses versioned compare-and-swap writes and logical revocation. The new migration is committed but not applied. No token refresh flow, production credentials, production API call, webhook, or UI status exists. Do not treat the start route or migration as a live connection. The client transport is a base for the following read-only API slice, not a general write API.

## Read-only transport correction (2026-10-24)

The initial `graphql-client.mjs` accepted arbitrary GraphQL documents despite `writesEnabled: false`. The isolated follow-up `fix/linear-graphql-readonly` adds a GraphQL-aware lexical scan before transport: it rejects mutations, subscriptions, invalid/ambiguous operation selection, and multi-operation documents without a uniquely matching `operationName`. It ignores comments and string/block-string contents while classifying operations, and includes tests proving rejected documents never call `fetch`. Multiple read operations are allowed only with an explicit operation name. This is a narrow operation-kind guard, not a full GraphQL validator; Linear remains responsible for schema and document validation. The targeted connector test file passes 11/11 locally. No Linear API request or live deployment was made.

## API behavior checked against Linear documentation

- Linear recommends OAuth 2.0 for third-party applications. Its authorization URL is `https://linear.app/oauth/authorize`; send `response_type=code`, callback, scope, and CSRF-protected state. PKCE uses `code_challenge` with `S256`.
- Authorization codes are exchanged by form POST to `https://api.linear.app/oauth/token`; the callback URI must match. PKCE sends the original verifier. Access and refresh tokens are returned; access tokens expire after 24 hours and must not be treated as durable API keys.
- The public API is GraphQL at `https://api.linear.app/graphql`; OAuth bearer credentials are sent in the `Authorization` header.
- Supported narrow scopes documented by Linear include `issues:create` and `comments:create`; `admin` is described as full admin access and should be avoided unless essential. This contract does not request `write` or `admin`.

Sources: [Linear OAuth 2.0 authentication](https://linear.app/developers/oauth-2-0-authentication), [Linear GraphQL getting started](https://linear.app/developers/graphql), [Linear API and webhooks](https://linear.app/docs/api-and-webhooks). Documentation checked 2026-10-24.

## Encrypted token store slice (2026-10-24)

- `token-vault.mjs` encrypts access and refresh tokens independently with AES-256-GCM, 96-bit random nonces, 128-bit tags, and AAD containing provider, schema version, both ATLAS IDs, both Linear IDs, token type, and key ID. Missing, malformed, unknown, or mismatched keys fail closed.
- Server key configuration names: `LINEAR_OAUTH_TOKEN_KEYS` (JSON key-ID to base64 32-byte key map) and `LINEAR_OAUTH_TOKEN_KEY_ID` (current key ID). Keep the whole keyring in a server secret manager. Rotation requires adding a new key version, selecting it as current, re-encrypting each actor connection with the existing row version, verifying successful CAS, then retiring an old key only after no stored rows reference it. No key value belongs in Git, logs, or client configuration.
- Migration `20261024103000_atlas_linear_oauth_connections.sql` adds one credential row per `(ATLAS workspace, ATLAS actor)`, references live `workspace_members` with cascade on membership removal, enables RLS with no client policy/grants, grants the service role only SELECT/INSERT/UPDATE, and restricts save/revoke RPC execution to service role. Database version CAS makes key re-encryption, reconnect and logical revoke race-safe. Reconnect clears the revoke marker only on a version-matched update. Removing an ATLAS workspace membership deletes its local ciphertext row but does not revoke the grant at Linear; provider-side revocation remains a separate action.
- The callback checks the current owner/admin membership and state actor, consumes the one-time state, checks the connection table is deployed before exchange, requests `read` only, calls the fixed Linear GraphQL endpoint to verify `viewer.id` and `viewer.organization.id`, then persists the actor-specific encrypted record. The current official Linear schema includes `Query.viewer: User!` and `User.organization: Organization!`; the OAuth guide documents `viewer` identity queries. See [Linear OAuth 2.0](https://linear.app/developers/oauth-2-0-authentication), [Linear GraphQL](https://linear.app/developers/graphql), and the [current official schema](https://raw.githubusercontent.com/linear/linear/master/packages/sdk/src/schema.graphql). If identity or persistence fails after exchange, it makes best-effort fixed-endpoint revocation for both tokens and returns only a fixed status. The callback remains disabled by default.
- Unit tests exercise ciphertext, tamper detection, wrong key/context, key rotation, actor and workspace isolation, member denial, safe callback success/failure, and no exchange when disabled. CI applies this migration only to its ephemeral PostgreSQL 17 fixture and tests role grants, RLS, membership binding, logical revoke, and concurrent version CAS. This is not proof that the new CI job has passed until a run for the resulting head is observed.
- The migration is not applied to Supabase production; no OAuth code was exchanged and no real Linear API request was made during this implementation. OAuth callback activation requires an explicit separate release decision after CI and application-level review. Refresh, a real managed secret-store setup, and runtime validation against the actual current Linear schema remain outstanding.
